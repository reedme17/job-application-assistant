# Truthful resume tailoring

The base resume and explicit user-confirmed facts are authoritative. An unanswered profile field is unknown. If sources conflict, request resolution for affected content while continuing unaffected preparation.

Allowed edits: reorder relevant skills or bullets, choose relevant existing projects, shorten less relevant content, clarify language, and adjust summary emphasis. Use JD terminology only when supported by the candidate's actual experience. Preserve employers, official titles, dates, degrees, seniority, project ownership and metrics. Do not upgrade participation to leadership or transform adjacent exposure into proficiency. Never invent tools, certifications, achievements, years, or numbers.

Identify hard mismatches and distinguish them from missing information. Explain genuine gaps instead of hiding them through wording. Write short screening answers from existing facts; leave unsupported claims pending. Do not make promises about passing ATS filters or securing interviews.

Preserve the base resume's effective layout and requested length. If no template exists, use a restrained single-column document with selectable text, standard section labels and readable spacing. Avoid keyword stuffing and hidden text. Keep the source resume unchanged and create separate versions per job.

For PDF input/output, read `pdf-tools.md` and use the bundled extraction, generation, checking and rendering commands. Edit the intermediate JSON using confirmed source facts; preserve the original PDF and baseline JSON. This rebuilds the document instead of editing the original layout in place. Use available document tools for DOCX when required. If dependencies cannot be installed or a format cannot be rendered correctly, deliver the editable source and state that upload-ready output is pending. Do not rename a text file to .pdf or .docx.

Before upload, inspect rendered pages for clipping, blank pages, broken spacing and missing content; check extracted text/order and contact details against the source. Save meaningful changes and their factual support in `changes.md`. If upload-ready rendering or validation fails, do not silently use an unverified replacement.
